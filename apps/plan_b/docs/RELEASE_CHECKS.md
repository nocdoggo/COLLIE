# Release checks (Wave 3, W3.3)

This page maps each reliability and UX release check in
`PEEAI_plan/waves/03_evidence_showcase.md` ("Reliability and UX release checks"), and each item
of the "Small functional check set" in `PEEAI_plan/08_evaluation.md`, to the automated tests that
cover it. Every status is either a passing test, N/A with the reason, or a recorded defect.

These checks are separate from the measured policy episodes. They change no frozen file:
`uv run plan-b eval verify-freeze --require-heldout` passes with them in place. The web is not
part of the measured behavior, and `freeze.json` hashes no file under `web/`. Model-driven
policies run here with a scripted transport (`tests/test_agent_provider.py` `FakeOpener`), so
these checks make no paid call and need no network.

Run them from `apps/plan_b` with `unset VIRTUAL_ENV`:

| What | Command |
| --- | --- |
| Python checks (part of the default pytest run) | `uv run pytest tests/test_release_failures.py tests/test_pantry_workflow.py` |
| Web checks | `cd web && npm run typecheck && npm test && npm run lint && npm run build` |
| Keyboard and comprehension (browser) | `uv run python tests/e2e/keyboard.py --out <dir>`, after `npm run build` |

The browser script starts `plan-b serve` on 127.0.0.1 with a fresh state directory and removes
the directory afterwards. It uses the deterministic policies only, and it writes
`keyboard_report.json` plus the Tab order of both boards into `<dir>`.

## Defects found

No release check exposed a defect in frozen code, so no test is kept as `xfail`.

Known limitation of frozen code, seen outside these checks: a provider error, including an HTTP
429 rate limit, counts as one of the episode's 8 model calls, and the retry comes at the next
scenario wake with no wall-clock backoff. It voided attempt 1 of the held-out run
(`evaluation/results/wave3_heldout_20261025T1625Z/README.md`); no reported episode had a
provider error. For live use, run one model-driven episode at a time and keep the offline
replay as the fallback. The post-run audit also found a frozen planner-input defect that affected
measured pantry episodes (an `unavailable` pool kept as a handoff option); it is recorded with
the results (`FAILURES.md` there), not as a release check.
